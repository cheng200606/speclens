## 1. I8① 路由诊断与 v3（关闭转移鸿沟的关键）

### 诊断（离线，零 API）

- **需求编号首位 cue**：asvs 断言以「V6.2.9: …」开头 → 首位派生 cue=需求编号，
  该 token 只存在于规范文本、永不出现在代码 → **12 条 matched 规则路由全灭**。
- 单复数不匹配（passwords vs password）；snake_case 标识符（password_changed_at）
  被 `\b` 边界整体漏掉。

### routing v3（全部确定性）

1. `_derived_cues` 过滤规范 ID token；`_GENERIC` 补 ASVS 叙述词。
2. 匹配改为**代码词元集**（`_`/驼峰切分、小写）× cue 形态变体
   （s/es/ies 折叠），保留 use(/useHook 调用形态特判——词汇路由的精确化。
3. **不对称政策（D8-1）**：matched（canonical-ID）规则全局配对（≤12 条/规范，
   有界）——「必须使用 X」型规则的违规文件缺少 X 词元，词汇路由有原理性盲区；
   X-合成规则保持 cue 严格（成本闸门）。溯源不涉及标注（无泄漏）。
4. **库内文档频率排名 + 每文件上限 30**：命中 cue 的 bank-df 升序（稀有 cue
   高特异性），泛命中洪泛的确定性上限。
